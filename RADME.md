# Развёртывание и сопровождение веб-проекта

## Тема проекта

**Развёртывание и сопровождение веб-проекта с мониторингом, централизованным логированием и резервным копированием.**

## 1. Описание проекта

В рамках курсового проекта развёрнута инфраструктура веб-приложения на базе WordPress с балансировкой нагрузки между двумя серверами приложений.

Инфраструктура включает:

- веб-сервер Nginx, выполняющий функции обратного прокси и балансировщика нагрузки;
- два сервера WordPress;
- сервер базы данных MariaDB с настроенной репликацией;
- систему мониторинга на базе Prometheus и Grafana;
- централизованный сбор логов на базе Graylog;
- отдельный сервер резервного копирования;
- маршрутизатор с межсетевым экраном UFW для разделения сетевых сегментов;
- Ansible для автоматизации развёртывания и настройки инфраструктуры.

Конфигурации и сценарии автоматизации хранятся в Git-репозитории.

## 3. Веб-приложение

В качестве веб-приложения используется WordPress.

Схема обработки запросов:

1. Пользователь обращается к веб-сайту по HTTPS.
2. Запрос поступает на сервер `k-front`.
3. Nginx выполняет балансировку нагрузки между `k-b1` и `k-b2`.
4. Серверы WordPress обращаются к базе данных MariaDB.
5. База данных работает по схеме Primary / Replica.

Соединение между Nginx и серверами WordPress осуществляется по HTTP. HTTPS используется на внешнем участке между клиентом и фронтендом.

Адрес веб-приложения: `https://kurs.dmitlabs.com`.

## 4. База данных

Используется MariaDB 10.11.14.

Развёрнуты два сервера:

- `k-db1` — основной сервер (Primary);
- `k-db2` — сервер-реплика (Replica).

Настроена репликация на основе GTID.

## 5. Мониторинг

Для мониторинга инфраструктуры используются:

- Prometheus — сбор и хранение метрик;
- Node Exporter — получение системных метрик серверов;
- Grafana — визуализация метрик и мониторинговые панели.

Prometheus собирает метрики с серверов инфраструктуры. Настроено 9 целей мониторинга, все находятся в состоянии UP.

В Grafana настроен источник данных Prometheus и установлен дашборд Node Exporter Full.

## 6. Централизованное логирование

Для централизованного сбора и анализа логов используется Graylog 7.2.2.

Компоненты сервера `k-log`:

- Graylog;
- MongoDB 8.0;
- Graylog Data Node.

Настроен приём системных сообщений через Syslog UDP Input на порту 1514.

Для передачи системных журналов используется rsyslog.

## 7. Резервное копирование

Для резервного копирования используется отдельный сервер `k-backup`.

Настроено автоматическое резервное копирование базы данных MariaDB:

- ежедневное выполнение в 02:00;
- хранение резервных копий в течение 7 дней;
- передача копий на сервер резервного копирования.

Проверено восстановление базы данных из резервной копии.

## 8. Сетевая безопасность

Для маршрутизации и фильтрации трафика используется `k-net` с UFW.

Основные принципы фильтрации:

- входящие подключения по умолчанию запрещены;
- исходящие подключения разрешены;
- транзитный трафик по умолчанию запрещён;
- разрешён HTTPS-трафик к фронтенду;
- разрешён HTTP-трафик от фронтенда к серверам WordPress;
- разрешены необходимые исходящие DNS, HTTP, HTTPS и NTP-соединения из внутренней сети;
- SSH разрешён для Ansible-контроллера и административных сетей;
- доступ Ansible к фронтенду по SSH разрешён отдельным правилом.

## 9. Автоматизация развёртывания

Для автоматизации настройки серверов используется Ansible.

Управление инфраструктурой осуществляется с сервера `k-ans`.

Основные компоненты проекта:

- `inventory/` — инвентарный файл серверов;
- `playbooks/` — сценарии настройки и развёртывания;
- `ansible.cfg` — конфигурация Ansible.

Изменения конфигурации инфраструктуры выполняются через Ansible Playbook.

Развёртывание и настройка компонентов автоматизированы с помощью Ansible. Конфигурации проекта хранятся в Git.
